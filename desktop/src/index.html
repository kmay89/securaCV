🛡 Board new to you? Hold BOOT while plugging in

A board from a shop or marketplace arrives running someone else's firmware. On a native-USB board (S3 and C-series) that firmware can present itself to your computer as anything, even a keyboard, the moment it's plugged in. No app can step in front of that. Holding BOOT keeps it from ever running:

  1. Unplug the board.
  2. Press and hold BOOT (marked B).
  3. Still holding it, plug the cable in. Then let go.

No BOOT button, or no USB port? A classic ESP32 (ESP32-CAM, plain WROOM DevKit) talks through a separate USB-serial chip, so its firmware can only ever be a serial port and cannot pretend to be a keyboard. To keep its firmware from running, jumper IO0 to GND before you apply power. Per-board wiring is on the board's card below.

Held correctly, the chip comes up in its mask-ROM download mode and the shipped firmware never runs. That's the chip's own silicon, not a promise from this app, and it's the same property that makes the board impossible to brick from here.

The security fuses are the one thing a previous owner can change that no erase undoes.

Have a Canary WAP running? Check it over Bluetooth

A WAP keeps a read-only Bluetooth console up even without Wi-Fi. This window has no Bluetooth of its own, so the check runs in the browser Lab in Chrome or Edge on this computer.

Found, but not identified?

Hold BOOT, tap RESET, release BOOT. It's read again automatically. Tap RESET later to leave download mode.

    ⚙
    Advanced
    
            
    Optional. Most people never need these.
    

            
    
              Safety copy
              
    Before every write, the whole chip is saved to this app's backups folder.
                It's your undo: restore it from Rescue below. Skipping saves about a minute per board.
    
              
            
    

            
    
              Diagnostic report
              
    Copies what a bug report needs (build, platform, chip, USB device, firmware, last
                error, console tail) to your clipboard. Nothing is sent anywhere.
    
              
    
                
                
              
    
              
              
            
    

            
    
              Dev channel
              
    Flash the rolling fw-dev-latest prerelease instead of the
                stable release. Same checks: chip guard, SHA-256, release signature. The banner
                says which version it carries.
    
              
            
    

            
    
              Install a local file
              
    Write a factory .bin from your computer
                (dev_flash.sh <env> -f or
                firmware/scripts/make_factory.py makes one). An app-only
                build is refused. Its signature can't be checked, but the board still can't be bricked.
    
              
    
                
                
              
    
              
    
                
    Size—
    
                
    SHA-256 fingerprint—
    
                
    We can't vouch for a personal file's origin — that part is on you.
    
                
    
                
    
              
    
              
    
                
              
    
              
    
              
    
            
    

            
    
              Health check (read-only)
              
    Reads the partition map, the firmware in each slot, update history, crash dumps
                and the witness chain, then gives a plain verdict. Nothing is written. Keys and
                passwords are never shown — only whether they exist.
    
              
    
                
              
    
              
    
              
    
              
    
              
    
            
    

            
    
              Rescue: back up, restore, or erase
              
    A backup holds everything on the board, identity key and saved Wi-Fi
                included — store the file like a house key. None of this can brick the board.

    Wi-Fi & account

              Home Assistant account (skips the setup wizard)
              
    Type a login now and this app creates it on the hub after first boot, then
                checks it works. Keep the app open until then. Leave it blank to set up on first visit.
    
              
    
                
                
                
                
              
    
              
    
            
    

            
    
              Self-setup: broker, MQTT, Frigate, securaCV
                on by default
              
    The card carries a setup bundle and a maintenance key made on this computer.
                Once the hub is up, this app installs everything over your network. No monitor or
                keyboard on the Pi; the SecuraCV iPhone app can do the same steps if this app is closed.
    
              
    
                About the maintenance key
                
    Its private half stays in this app's data folder. To revoke it, delete
                  authorized_keys from the card's boot partition, or re-flash
                  without this option. Honest status: the bundle is proven at the desk, not yet on a
                  real first boot; a bundle that never runs is harmless.
    
              
    
              
              
    Pi-hole — a DNS service that shows every
                domain every device on your network asks for, so you can see nothing phones home. It also
                blocks known ad and tracker domains. Does nothing until you point your router's DNS at the hub.
    
              
    
                What Pi-hole records
                
    To say which device asked for a domain, its query log keeps the client IP
                  (and hostname), the domain, and the time. Not page contents. The log stays on your hub;
                  Pi-hole's settings let you shorten retention or turn logging off (blocking still works).
    
              
    
              
              
    Hub display — for an HDMI screen plugged into
                the Pi. Installs HAOSKiosk, which shows your dashboard full-screen, touch included. Headless stays the default.
    
              
    
                Setting up the screen afterward
                
    The screen needs its own Home Assistant login, and no password is ever put
                  on the card. In HA: Settings → People → Users → Add User (name it “screen”, Administrator
                  off). Then Settings → Apps → HAOS Kiosk Display → Configuration, enter that login, press
                  Start. Zoom, rotation and timeout live in the same tab. No screen attached? The app
                  simply won't start.
