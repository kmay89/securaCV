Put the Lab on your iPad

Follow this top to bottom. Every command is copy-paste, every step tells you exactly what success looks like, and every step has a "if it goes wrong" you can open. Don't skip — each step assumes the one above it worked.

🖥️ On a Mac — required ⏱️ ~30 min first time 💳 Free Apple ID is enough to start
Before you start — check all four

Tick each box once it's true. If any is missing, fix it first — the steps below will fail without them. These are one-time installs; you'll never do them again.

🚦 Prerequisitesall four must be green before Step 1
The five steps
  1. 1

    Add the iPad build targets to Rust

    Tells Rust how to compile for the three iPad/iPhone chip targets. One-time.

    $ rustup target add aarch64-apple-ios aarch64-apple-ios-sim x86_64-apple-ios
    ✓Success looks like: each target prints "info: installing component" or "is up to date". No red error text.
    ▶ If it goes wrong
    command not found: rustup
    Rust isn't installed. Install it from rustup.rs, open a new terminal, and try again.
  2. 2

    Go into the app folder and install its dependencies

    Everything from here runs inside desktop-lab/. This is the same folder that builds the Mac and Linux apps.

    $ cd desktop-lab
$ npm install
    ✓Success looks like: npm finishes with "added N packages" and returns you to the prompt with no errors.
    ▶ If it goes wrong
    no such file or directory: desktop-lab
    You're not in the repo root. cd into your clone of the securaCV repo first, then run the commands.
    command not found: npm
    Node isn't installed. Get Node 20+ from nodejs.org, open a new terminal, retry.
  3. 3

    Generate the iPad (Xcode) project

    Builds the Xcode project from the app's config. You never edit it by hand — if it ever breaks, you just run this again.

    $ npm run ios:init
    ✓Success looks like: it creates a src-tauri/gen/apple/ folder and finishes with "iOS project generated".
    ▶ If it goes wrong
    You have not agreed to the Xcode license
    Run sudo xcodebuild -license accept, then run npm run ios:init again.
    xcrun: error: unable to find utility "xcodebuild"
    Command Line Tools aren't set. Run sudo xcode-select --switch /Applications/Xcode.app and retry.
  4. 4

    Run it in the iPad Simulator

    Builds and launches the Lab. When it asks which device, pick an iPad (e.g. iPad Pro), not an iPhone — that's the only choice that matters for the iPad layout.

    $ npm run ios:dev
    ✓Success looks like: the iPad Simulator opens and the Lab appears with its sidebar on the left (iPhone would show a bottom tab bar instead). Edits you make to the Lab reload live.
    ▶ If it goes wrong
    No iPad in the device list
    Open Xcode ▸ Settings ▸ Platforms and make sure an iOS Simulator runtime is downloaded, then rerun.
    It opened an iPhone, not an iPad
    Stop it (Ctrl-C), rerun npm run ios:dev, and choose an iPad from the list. Or launch an iPad simulator first from Xcode ▸ Open Developer Tool ▸ Simulator.
  5. 5

    (Optional) Make an installable build

    Only needed to put it on a real iPad or TestFlight. For just trying it out, Step 4 is enough — you're already done.

    # unsigned build (for the Simulator)
$ npm run ios:build
    # put it on YOUR OWN iPad (free Apple ID) —
# replace XXXXXXXXXX with your 10-character Apple Team ID
$ export APPLE_DEVELOPMENT_TEAM=XXXXXXXXXX
$ npm run ios:build -- --export-method debugging
    ✓Success looks like: it finishes with a path to an .ipa file. That's your installable app.
    Match the --export-method to where it's going — the wrong one fails signing. debugging uses a free Apple Development certificate (your own iPad); TestFlight and the App Store need the paid $99/yr Apple Developer Program:
    FREEdebugging — your own iPad, 7-day install. This is the command above.
    PAIDrelease-testing — TestFlight (Apple Distribution cert).
    PAIDapp-store-connect — the App Store (Apple Distribution cert).
    ▶ If it goes wrong
    No signing certificate / provisioning profile
    Find your Team ID at developer.apple.com ▸ Membership, set it in the export line above, and make sure your Apple ID is added in Xcode ▸ Settings ▸ Accounts. Free-tier device installs expire after 7 days — just rebuild to renew.

What works on iPad (and what can't)

iPad is a locked-down platform on purpose. The Lab is honest about it — anything it can't do is hidden, never a dead button. Nothing here is a bug to fix.

On iPad, the Lab can…
HIDDENFlash a Canary over USB — Apple blocks USB-serial on iPad. This bench is hidden and points you to the Mac app instead.
NATIVEFind your Canaries on the network — Bluetooth + Bonjour discovery, live on your iPad.
NATIVENotify you on signed events — native iPad notifications.
NATIVEStore data sealed on-device — Keychain-backed. Talks only to your own devices.
