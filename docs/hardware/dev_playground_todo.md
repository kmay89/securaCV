# Dev Playground — TODO & handoff

**Read this first if you're picking up the Waveshare 4.3B dev playground.**
It's the map of where everything lives, the exact ritual to add or change a
station, the gotchas that will bite you, and what's worth doing next. The
playground itself is documented for *users* in
[`dev_playground_43b.md`](./dev_playground_43b.md); this file is the
*maintainer's* continuation note.

---

## What the playground is

A safe, guided peripheral test bench: the Waveshare ESP32-S3-Touch-LCD-4.3B
runs a network-silent "bench mode" (firmware env `canary-display-playground`,
`FEATURE_PLAYGROUND=1`) where you wire a peripheral onto the 16-way terminal
block, the glass shows how to wire it + the bring-up code, and you poke it and
watch the device's own `PG1` serial text. The **same** behavior is reproduced
in a browser (canary-local page + the securacv_website 3D playground) so it can
be demoed with no hardware.

**Current stations (10):** `doorbell` (DI0), `intrusion` (DI1), `chime` (DO0),
`strobe` (DO1), `light` (I²C VEML7700/BH1750), `tof` (VL53L0X), `captouch`
(MPR121), `rs485` (A/B · Modbus RTU), `can` (H/L · TWAI), `census` (I²C scan).

## The drift-lock chain (where every piece lives)

CI **drift-gates** these against each other, so a change in one that isn't
mirrored in the others breaks the build. In dependency order:

| Layer | Path | Role |
|---|---|---|
| Firmware — cards/UI | `firmware/projects/canary-display/src/playground/playground_ui.cpp` | `META[]` station cards + wiring **instructions** + `card_value` |
| Firmware — drivers | `firmware/projects/canary-display/src/playground/playground.cpp` | the `PG1` driver: `action_*`, SNAP, timers |
| Firmware — state | `firmware/projects/canary-display/include/canary/playground/playground.h` | `PgState` members + `action_*` prototypes |
| **Arduino mirror** | `firmware/projects/canary-display/arduino/canary_display/playground*.cpp` | GENERATED by `setup.sh regen`; **the JS test greps THESE, not `src/`** |
| Generator | `canary-local/tools/gen_playground.py` | emits `playground.json` from the firmware + `pins.h` |
| Data (generated) | `canary-local/devices/playground.json` | terminals, stations, wiring prose, bring-up code, `PG1` grammar |
| Sim (behavior) | `canary-local/assets/playground-sim.js` | DOM-free JS port of the firmware driver |
| Test (the gate) | `canary-local/tests/playground.test.js` | honesty + behavior; pins the sim to the `.cpp` constants |
| Website — data | `securacv_website/js/playground-data.js` | CARRIED copy of `playground.json` (`export const PLAYGROUND = …`) |
| Website — sim | `securacv_website/js/playground-sim.js` | CARRIED copy of `assets/playground-sim.js` |
| Website — renderer | `securacv_website/js/playground.js` | three.js 3D bench: `_poke(action)` dispatch + `PERIPHERAL` 3D bodies |
| Website — page | `securacv_website/playground.html` | loads the three modules |

## The ritual: adding or changing a station

1. **Firmware** (`src/playground/`): add the `Station` enum value, a `META[]`
   card entry (wiring **instructions** written for the glass), the `card_value`
   case, the `action_*` driver in `playground.cpp`, and the `PgState` member +
   prototype in `playground.h`. New stations are **EVT-only** (see gotchas).
2. **Generator** (`gen_playground.py`): add the station dict — `id`, blurbs,
   `wires`, **instructions (must be byte-identical to the firmware META prose)**,
   `code`, `stimulus`, `expect`. Add pin-tracker + terminal/colour entries if the
   station lands on a new terminal.
3. **Regenerate the data:** `python3 canary-local/tools/gen_playground.py`
   (writes `canary-local/devices/playground.json`).
4. **Sim** (`assets/playground-sim.js`): add the field(s) to `freshState()` and
   the driver method(s) that emit the exact `PG1` lines.
5. **Test** (`tests/playground.test.js`): add behavior cases. Run
   `node --test canary-local/tests/playground.test.js` (was **16/16** at handoff).
6. **Regenerate the Arduino mirror:**
   `cd firmware/projects/canary-display && ./setup.sh regen` — the JS test greps
   the mirror, and `check_display_arduino_sync.sh` fails if it drifted.
7. **Carry to the website:**
   - `securacv_website/js/playground-sim.js` ← copy `canary-local/assets/playground-sim.js` **verbatim** (keep the 5-line website carry header).
   - `securacv_website/js/playground-data.js` ← website header + `export const PLAYGROUND = ` + `playground.json` body + `;` (one-space indent; `};` on one line).
   - `securacv_website/js/playground.js` → add the `_poke` case(s) for the new `action` string(s), and a `PERIPHERAL.<part>()` 3D body if the station uses a new `part`.
   - Sanity: `node --check` each of the three JS files; a headless `import` of the sim should reproduce the firmware's exact `PG1` lines.

## Gotchas that WILL bite you

- **Instruction prose is VERBATIM-gated.** `playground.test.js` squash-compares
  (`.replace(/[\\"'\s]/g,'')`, lines ≥ 8 chars) each station's JSON `instructions`
  against `playground_ui.cpp`'s `META[]`. Copy-paste; don't paraphrase.
- **The test reads the Arduino MIRROR, not `src/`.** Always `./setup.sh regen`
  before running the JS test, or you'll test stale prose/constants.
- **The SNAP line is exact-pinned** by the test (field order + formatting). Don't
  touch it — new stations emit `PG1 <ms> EVT <station> …` only.
- **`PG1` grammar:** `PG1 <ms> EVT <station> <k>=<v>…` and `PG1 <ms> SNAP …`.
- **Playground edits do NOT change the wasm dist.** `src/playground/*.cpp` is
  **not** in the emulator's `FIRMWARE_SRCS` (`canary-local/emulator/build.sh`),
  so a station change needs **no** `dist/*.js` rebuild. (If you ever edit files
  that *are* in `FIRMWARE_SRCS`, rebuild with `canary-local/emulator/build.sh all`
  — `emcc`/`em++` 3.1.6, `apt install emscripten` on ubuntu-latest — and confirm
  `dist/*.js` are byte-identical or commit the rebuild.)
- **The playground env has no `FEATURE_RS485`/`FEATURE_CAN`.** `rs485`/`can`
  stations INLINE `Serial1`/TWAI using the pure cores `canary/io/modbus_rtu.h`
  and `canary/io/can_frame.h` rather than the gated production drivers.
- **Website carry is a copy, not an import.** `playground-data.js` /
  `playground-sim.js` are hand-carried; re-carry them whenever `playground.json`
  or the sim changes (step 7). The `showroom.js ← assembly.json` pattern is the
  same idea.

## TODO — next stations (grounded in the capability-map backlog)

The firmware fieldbus/latent capabilities are now **built and compile-verified**
(see below), which makes several new stations cheap and honest:

- [ ] **RTC station (PCF8563).** The pure core already exists
  (`include/canary/io/rtc_pcf.h`, host-tested). A station could probe `0x51` on
  the shared I²C bus, show/set the time, and demo the **voltage-low (VL) flag**
  (unreliable-clock rejection). Lands on the existing `SDA`/`SCL` terminals — no
  new wiring. Good first add.
- [ ] **ESP-NOW peer station.** Show received peer **presence beacons** (fp4 +
  liveness) off the raw channel — the receive-only path from
  `canary/net/espnow_peer_logic.h`. No terminal wiring (it's radio); a "peer
  heard" readout. Needs a paired sender to demo live (see backlog).
- [ ] **microSD station.** Blocked: CS is on the CH422G expander (EXIO4), not a
  native GPIO — needs an SdFat software-CS callback. See capability map §5; treat
  as a bulk-archive stretch, not the evidence store.
- [ ] **1-Wire / DS18B20 temperature** *(only if a terminal pin is genuinely
  free — verify against `pins.h`; the 4.3B breaks nothing else out, so this may
  be N/A).*

When adding any of these, follow the ritual above **and** update the pin tracker
+ `docs/hardware/dev_playground_43b.md` station table.

## TODO — the real gating work (not playground code)

Everything the fieldbus/latent-capability PRs added is **`Built · bench-gated`**:
the code is written, host-tested, and compile-verified in dedicated CI envs, but
it is **off by default pending one bench session on real 4.3B hardware.** That
bench session is the highest-value remaining work, and it's the thing an AI
*cannot* do from CI — it needs eyes and a meter on the board.

Authoritative sources (keep these honest):
- [`board_capability_map_43b.md`](./board_capability_map_43b.md) — the ledger of
  every capability, its status, and the exact gate/bench step.
- [`board_43b_activation_bench.md`](./board_43b_activation_bench.md) — the
  executable per-capability bench checklist (wiring, flag, pass signal).

Bench-pending items and their one remaining step:

| Capability | Flag / env | Remaining bench step |
|---|---|---|
| Evidence vault | `FEATURE_TIME_MACHINE_PERSIST` · `-vault` | power-cycle reload + flash-wear soak, then flip default on |
| Isolated DI/DO + siren | `HAS_ISOLATED_IO` (shipped) + arm toggle | validate optocoupler DI + DO sink polarity (VERIFY-tagged in `pins.h`) |
| RS485 / Modbus | `FEATURE_RS485` · `-rs485` | TX/RX orientation + bus timing vs a real slave |
| CAN / TWAI | `FEATURE_CAN` · `-can` | TX/RX orientation, bit timing, 120 Ω terminator jumper |
| Trusted-time RTC | `FEATURE_RTC` · `-rtc` | confirm PCF8563 silicon + address on a real board, then flip on |
| ESP-NOW peer presence | `FEATURE_ESPNOW` · `-espnow` | paired **WAP-side ESP-NOW broadcast** of the beacon + WiFi-STA channel coexistence |
| microSD / RTC-battery | `HAS_SD_CARD` / `HAS_RTC`/`HAS_BATTERY` | confirm the silicon; SD needs SdFat software-CS on CH422G EXIO4 |

Once a capability is bench-validated and enabled *in the default build*, it can
also become a live playground station (the playground mirrors the **default**
build, so a gated-off capability can't be demoed until it ships on).

## Verify-everything commands

```sh
# playground drift gate (from repo root)
node --test canary-local/tests/playground.test.js

# regenerate + prove the generated data is clean
python3 canary-local/tools/gen_playground.py && git diff --stat canary-local/devices/playground.json

# arduino mirror in sync
firmware/scripts/check_display_arduino_sync.sh

# firmware guards touched by capability work
python3 scripts/lint_build_matrix.py
python3 firmware/scripts/check_board_registry.py
bash   firmware/scripts/test_feature_sanity.sh

# host tests for the pure cores (all print "ALL … PASSED")
g++ -std=c++17 -Wall -Wextra -Werror -I firmware/projects/canary-display/include \
    firmware/projects/canary-display/tests_host/test_rtc_pcf.cpp -o /tmp/t && /tmp/t
# (same pattern: test_field_io.cpp, test_espnow_peer.cpp, test_modbus_rtu.cpp, test_can_frame.cpp)

# emulator dist byte-identity (only if you touched FIRMWARE_SRCS files)
cd canary-local/emulator && ./build.sh all   # then cmp dist/*.js against HEAD
```

Voice rule (repo-wide): a group of Canaries is a **fleet**, never a "flock"
(only the Unix `flock(2)` syscall is exempt).
