## Summary

Every finding from the v1 audit is closed in code. Every follow-up listed in
PR #450's "Not in this PR (v0.3)" section is closed in PR #454. The
plan-vs-delivered check at the end of the original session is now 100%, save

## Findings closure

### Opera mesh — 3 of 3 closed

- **O1 (Medium)** — Wall-clock TTL `millis()/1000` removed; per-peer monotonic
  counter is now the authoritative freshness mechanism.
  `mesh_network.cpp:524-535`. Regression test:
  `test_mesh_opera_security::test_o1_counter_replay_protection`.
- **O2 (High)** — `opera_secret` NVS persistence gated on
  `esp_flash_encryption_enabled()`. Load/save paths refuse cleanly when FE
  is off and log to `LOG_CAT_CRYPTO` at `LOG_LEVEL_ALERT`.
  `mesh_network.cpp::flash_encryption_enabled` + `persist_opera_config` +
  `load_opera_config`. Tests:
  `test_o2_load_refuses_when_fe_off` + `test_o2_persist_refuses_when_fe_off`.
- **O3 (High)** — `remove_peer()` initiates a full transactional rekey:
  stages new `opera_secret`, encrypts under each surviving member's session
  key via `MSG_OPERA_REKEY`, waits for `MSG_OPERA_REKEY_ACK` from each,
  commits on all-ACK or 60 s timeout (unacked peers marked `PEER_STALE`).
  ACK is sent under the OLD opera_id so the initiator accepts it
  (fix from codex P1 review on #454). Tests:
  `test_o3_rekey_commits_on_all_acks` + `test_o3_rekey_timeout_marks_unacked_stale`.

### Beacon channel — full v0 introduced

The harm-reduction layer specified in `spec/beacon_channel_v0.md` shipped with:

- **Two-pubkey cryptographic co-signing** on every `BEACON_MSG_ALERT`, with
  both signatures verified against pubkeys in the local beacon set.
  `beacon_channel.cpp::handle_alert_frame`. Test: `test_beacon_origination.cpp`
  (9 invariant assertions).
- **X25519 + ChaCha20-Poly1305** encrypted COSIGN_REQ/RESP exchange between
  paired devices. X25519 keypair NVS-persisted (FE-gated) so reboots don't
  invalidate paired neighbors' stored pubkey.
  `beacon_channel.cpp::ensure_x25519_keypair`, `cosign_encrypt`,
  `cosign_decrypt`.
- **NFPA-72-style supervised health state**:
  `Normal | Trouble | Alarm | Supervisory`. Daily `BEACON_MSG_SELFTEST_OK`
  heartbeat with Ed25519 sign/verify round-trip; receivers transition to
  `Trouble` when a paired neighbor's selftest is >36 h absent.
  `recompute_trouble_reasons`.
- **Append-only audit log** as a ring buffer with persisted head pointer.
  Chain-hashed à la witness records. NVS-gated by flash encryption.
  Paged export via `GET /api/beacon/audit?offset=N&limit=M`.
- **Bearer-token-gated REST surface** on `/api/beacon/*`, wired into
  `canary_wap.ino` under `FEATURE_BEACON_CHANNEL` (off by default; turn-on
  is per-deployment).
- **Distinct airtime telemetry**: `airtime_governor::force_reserve_beacon`
  records into a separate ring so HA can publish
  `sensor.canary_<id>_beacon_airtime_pct` separate from Opera tamper/power.
- **CAP-aligned wire fields**: severity / urgency / certainty / msgType
  carry the OASIS CAP 1.2 enums verbatim. `scope = Private` always.
- **Non-impersonation contract** CI-enforced via
  `scripts/lint_no_impersonation.sh` + `scripts/lint_cap_mapping.sh`. The
  CAP mapping lint asserts every Beacon template has a mapping row in
  `spec/beacon_cap_gateway_v0.md` (caught 3 missing rows during v0.3).
- **Non-impersonation patterns**: `audible_chirp.h::PATTERN_BEACON_NOTES`
  uses 1200 / 1700 / 2200 Hz sequential tones, deliberately distinct from
  any reserved emergency-broadcast attention signal. No red colors in any
  alert/chirp/beacon firmware or UI source.

## CAP gateway — deferred to v0.4 (specified)

`spec/beacon_cap_gateway_v0.md` documents the inbound and outbound
interop, mapping tables, and non-impersonation contract. **No
implementation** in v0.2 or v0.3 — gateway pubkey provisioning, upstream
CAP-XML-DSig verification, and CAP-compatible audit export are queued.

## How to verify on-device (when hardware is available)

`docs/audit/hardware_verification_checklist.md` enumerates each of the 11
manual / multi-device hardware tests from the audit's verification plan
(§7 of the v1 audit doc). Each is mapped to:

- The finding it confirms.
- The pre-fix repro recipe (record artifact).
- The post-fix expected behavior.
- Where to capture the result (`docs/audit/repro/<finding_id>/`).

Sign-off requires recording every repro in that directory before any v0.3
firmware ships to a deployment where the harm-reduction features are
operationally relied upon.
