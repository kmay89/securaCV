# Common Firmware Core

Board-agnostic firmware logic shared across projects.

## Module Structure

Every directory under `common/`, as of 2026-10-09 (the tree used to foreground
a HAL and web/Bluetooth headers that nothing compiled, and listed 14 of the
directories; `firmware/scripts/check_common_build_reachability.py` now fails a
shared header that no compiled source or test includes).

There is no HAL here. `common/hal/` once held ten prototype-only headers
(GPIO, UART, SPI, I2C, timer, storage, crypto, Wi-Fi, BLE) that nothing
implemented or included, one of which did not parse as C++; they, the
`web/http_server.h` and `bluetooth/bluetooth_mgr.h` prototypes and
`core/ring_buffer.h` were deleted on 2026-10-09. A port that needs a HAL
designs it against the code that calls it.

Not here on purpose: the health log, mesh network, RF presence and web UI
live next to the canary-wap sketch (`firmware/projects/canary-wap/arduino/
canary_wap/{health_log,mesh_network,rf_presence,web_ui}.h`) and the PIO
tree's logger is `include/canary/log.h` per project. Unbuilt `common/`
scaffolds that shared those names were deleted (roadmap item 29) so an
include path can never pick the wrong one.

## Design Principles

1. **No board-specific code**: Common modules must not include pin mappings
   or board-specific peripherals; a project passes them in (pins come from
   `boards/<id>/pins/pins.h` on the project's include path).

2. **No configuration data**: Common modules must not embed configuration
   values. Configurations come from `configs/`.

3. **Interface-first design**: Each module exposes a clean C interface
   with init/deinit lifecycle and config structs.

4. **Testable**: Modules keep their logic in pure, hosted C++ so
   `firmware/tests_host` can run it without the Arduino toolchain.

## Usage

Include modules via their header files:

```cpp
// with -I firmware/common on the include path, as the project envs set it
#include "witness/chain_state.h"
#include "network/wifi_join_policy.h"
```

## Adding a New Module

1. Create a new directory: `common/<module>/`
2. Create the header file with interface definitions
3. Implement the module (implementation files go in project src/)
4. Document the module in this README
5. Ensure no board-specific dependencies
